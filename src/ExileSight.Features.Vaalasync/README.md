# Shop repricing

Async listing mode is the default (`listingMode: "async"`). Open the game's **Set Item Price** dialog yourself and focus its amount field. Each physical price-button click redeems one overlay-click token for one `SetListingAmount` action: Ctrl+A, Ctrl+V, with no Enter or clicks. Choose the currency in the game's dropdown and click **LIST ITEM** yourself. ExileSight never opens or submits this dialog.

Async amounts are positive whole numbers only, because the game's Set Item Price amount box accepts only whole numbers (confirmed in game). Suggestions round to the nearest whole number, away from zero at midpoint, with a minimum of 1; duplicate adjustment amounts are disabled. Custom amounts must already be whole numbers. Values above 1,000,000 are refused. `SetListingAmount` also rejects fractional and nonpositive amounts defensively. Display and paste use the same invariant formatting, with a dot for any decimal shown in an estimate or note-mode price and no thousands separators.

Omni over a priced item arms price adjustments from the copied note. For an unpriced item, choose **Set listing price…** in the omni hold menu. The panel says **No current price**, enables only custom pricing, and seeds that field from a poe.ninja estimate when available. Estimates are labeled separately and never become a fabricated current price or history observation. A late estimate cannot overwrite a custom edit, a send or a newer item read. Short-tap routing is unchanged. Currency reminders tell you when to change the game's dropdown; they perform no input.

Legacy note mode remains available as `listingMode: "note"`, or through the checkbox in **History / custom price / record purchase**. The checkbox reflects the saved setting and says **applies after restart** when it differs from the running mode. In note mode, open the game's note box yourself. Each click uses `SetPriceNote` to paste the full note with Ctrl+A, Ctrl+V, Enter. Note-mode suggestions retain decimal/fraction behavior: round away from zero at midpoint, divine/mirror to two decimals, and other currencies to two decimals below 10 or whole units at 10 and above. Nonpositive rounded prices are refused; prefixes are preserved.

The commands `vaalasync:minus1`, `vaalasync:plus1`, `vaalasync:minus10`, `vaalasync:plus10` and `vaalasync:custom` are `OverlayOnly` (D-084). BindingMapper rejects hotkey bindings, including persisted ones. After a successful send or an ambiguous failure (including exceptions and partial sends), buttons stay disabled until another omni press reads an item. An omni read during an in-flight send does not re-arm. The UI ignores subsequent clicks classified by WPF as part of a system double-click sequence, before token redemption.

Only explicit pre-input refusals (MissingToken, UsedOrUnknownToken, Expired, NotForeground, Undeclared and WrongAction) keep repricing armed. A generic Failed result does not prove that no keys went out. These attempts are logged as “Possibly set”; a fresh omni read is required before another action. Success displays and stores the gate's paste confirmation status once. An unpriced item's first attempt writes one history entry, without a second “Listed” entry; reopening an unpriced item does not record an observation of an estimate.

History is bounded to 500 listings, 50 entries per listing and 8 MB. Invalid history is moved to a timestamped `.corrupt` file and the shop starts with an empty history; the recovery path remains visible in the model status. If preservation fails, writing is disabled to protect the original. Whisper matches may use item name, base type or both, but remain uncertain evidence, never completed sales. No buyer name or raw whisper is stored.

Price estimates and new listing history share one effective league captured for each item read: configured `prices.league`, otherwise the current softcore challenge default from the shared poe.ninja league request, otherwise Standard. Stale or failed discovery uses Standard, even if an earlier read discovered a seasonal league. Discovery starts only on demand and retains the price service's persisted hourly throttle; there are no startup requests or polling timers.

While discovery is pending, the panel opens with actions disabled and no history row is written. The asynchronous continuation records a priced item's observation and enables actions only after resolving its league; an unpriced item's first send records the same league used for its estimate. A newer read supersedes pending work. Resolution never sends game input. Manual purchase recording also awaits league resolution before saving.
