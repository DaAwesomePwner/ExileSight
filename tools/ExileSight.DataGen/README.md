# Data pack generation

Run `dotnet run --project tools/ExileSight.DataGen -- poe1 --out <directory> [--repoe-sha <full-40-hex-sha>] [--source-dir <local-export>]`.
The embedded `repoe.json` pins export `d0bc438357d849bb93ad22f3db0b12938aaf6da1`, game version label `3.29.3.4`. An explicit `--repoe-sha` overrides the pin and must still be a full commit SHA. The label describes only the default export; it is not inferred for overrides.
Only base_items.json and mods.json are consumed. Local input hashes are recorded but local input provenance cannot be authenticated by the converter.
Never commit generated game data. D-047 authorizes publishing generated packs as ExileSight GitHub release assets with RePoE and Grinding Gear Games attribution.

Schema 2 emits content, manifest, a local cache envelope, and SHA256SUMS. All output uses fixed LF newlines and invariant JSON formatting. Content hashes cover exact emitted UTF-8 bytes; cache envelopes retain those bytes as base64 and validation never re-serializes content. Schema 1 envelopes must be regenerated. Pack version is the full source commit. `gamePatch: unknown` and Unix epoch `generatedAt` are explicit unknown sentinels: the export does not provide trustworthy patch/time metadata, and wall-clock timestamps would break reproducibility. Input bytes and SHA fully determine output.

Tier estimates group by domain, generation type, groups and stat IDs within an item class and complete base-tag set. The first matching spawn weight determines eligibility, including zero-weight exclusions. Only item-domain prefix/suffix mods on item-domain bases are ranked; implicit, corrupted, crafted-domain and other unsupported mods remain explicitly unranked. Identical eligible family ladders are stored once, with class/tag contexts referencing stable hash IDs. Descending required level gives dense ranks (equal levels tie and ordinal mod IDs give stable ordering); these are level-order estimates, not official tiers or guaranteed power rankings. Stat IDs serve as unresolved text-template lookup IDs; translated text is not bundled. Unique drop tiers remain null/unknown.

Loader startup calls `ReadLocalAsync` only. A caller may schedule and await `RefreshAsync` later; unavailable packs do not prevent startup. Cache and fallback directories are supplied by the host. Refresh checks are throttled per release tag and pack ID for at least one hour, including failures. A different tag bypasses freshness. Valid cache envelopes persist the tag, successful check time and ETag; conditional requests require a valid matching cache. A 304 without one triggers a full GET. Cache envelopes replace atomically. The transport owns a SocketsHttpHandler with automatic redirects disabled and validates every manual redirect before sending (maximum five). Only HTTPS github.com, objects.githubusercontent.com and release-assets.githubusercontent.com are accepted. A handler factory exists solely for offline tests. Asset reads are streamed with a configurable 32 MiB default limit, including responses without Content-Length. Release tags and asset names allow only ASCII letters, digits, dots, underscores and hyphens, rejecting empty strings and `..`.

## Manual release workflow

In GitHub Actions, select **Release PoE1 data packs** (`release-packs.yml`) and **Run workflow** on the intended revision. Enter a pack version such as `3.29.3.4-1`. Leave the RePoE SHA blank to use `repoe.json`, or supply an explicit full 40-hex commit. Keep **dry_run** enabled (the default) to test and inspect the downloadable `poe1-packs` workflow artifact without creating a release. **prerelease** defaults to true; disable it only when intentionally publishing a stable pack release.

The workflow installs the exact SDK from `global.json`, runs DataGen tests, fetches only `data/base_items.json` and `data/mods.json` from the pinned raw.githubusercontent.com URLs without redirects, and generates packs. It checks SHA256SUMS, exact content hashes, cache bytes, source/input provenance, attribution, schema/pack identities and the loader's default content-size limit before uploading the artifact (retained for 14 days). SDK/package setup uses the normal .NET installation and restore infrastructure; game-export fetches use only GitHub hosts.

With **dry_run** disabled, a separate job uses only GITHUB_TOKEN with contents-write permission to create `poe1-packs-<version>` as a draft, upload assets, and publish it. It never marks a pack release as the repository's latest application release. Existing tags/releases are not overwritten; choose a new version. If upload fails, inspect the retained draft before retrying.

Release assets are `poe1-bases.json`, `poe1-mods.json`, their `.manifest.json` and `.pack.json` counterparts, and `SHA256SUMS`. The workflow artifact also includes `RELEASE-NOTES.md`; its attribution and source SHA become the release body. The manifest pack version remains the full source SHA: the workflow's version labels the release only. Tier estimates are included in the mods pack. No separate tiers asset is emitted.

Pass the exact `poe1-packs-<version>` tag to `PackLoader.RefreshAsync`. It downloads the `.manifest.json` and `.json` assets from `https://github.com/DaAwesomePwner/ExileSight/releases/download/<tag>/`; no latest-release lookup is involved. The `.pack.json` files are validated cache/fallback envelopes for offline use. Publish in that repository for the current loader to find the assets.
