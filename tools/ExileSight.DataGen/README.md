# Data pack generation

Run `dotnet run --project tools/ExileSight.DataGen -- poe1 --out <directory> [--repoe-sha <full-40-hex-sha>] [--source-dir <local-export>]`.
The embedded `repoe.json` pins export `d0bc438357d849bb93ad22f3db0b12938aaf6da1`, game version label `3.29.3.4`. An explicit `--repoe-sha` overrides the pin and must still be a full commit SHA. The label describes only the default export; it is not inferred for overrides.
The base_items.json, mods.json and English stat_translations.json exports are consumed. Local input hashes are recorded but local input provenance cannot be authenticated by the converter.
Never commit generated game data. Generated packs are published as ExileSight GitHub release assets with permission of the project owner, with RePoE and Grinding Gear Games attribution. This product is not affiliated with or endorsed by Grinding Gear Games.

Schema 3 emits content, manifest, a local cache envelope, and SHA256SUMS. All output uses fixed LF newlines and invariant JSON formatting. Content hashes cover exact emitted UTF-8 bytes; cache envelopes retain those bytes as base64 and validation never re-serializes content. Schema 1/2 envelopes must be regenerated. Pack version is the full source commit. `gamePatch: unknown` and Unix epoch `generatedAt` are explicit unknown sentinels: the export does not provide trustworthy patch/time metadata, and wall-clock timestamps would break reproducibility. Input bytes and SHA fully determine output.

Tier estimates group by domain, generation type, groups and stat IDs within an item class and complete base-tag set. The first matching spawn weight determines eligibility, including zero-weight exclusions. Only item-domain prefix/suffix mods on item-domain bases are ranked; implicit, corrupted, crafted-domain and other unsupported mods remain explicitly unranked. Identical eligible family ladders are stored once, with class/tag contexts referencing stable hash IDs. Descending required level gives dense ranks (equal levels tie and ordinal mod IDs give stable ordering); these are level-order estimates, not official tiers or guaranteed power rankings. Mod TextTemplateIds reference entries in the separate poe1/stats pack, filtered to translations sharing a stat ID with a packed mod (including partial hybrid entries). Translation IDs are stable within the pinned export. Hidden entries and all handler names are retained. The pure StatText matcher returns every candidate, retaining range endpoints when no rolled value is present; numeric handlers are inverted and conditions checked against raw values. Unsupported lookup handlers and compositions with multiple rounding stages fail closed. Ignored values are recovered only from exact conditions; otherwise no candidate is returned. Unique drop tiers remain null/unknown.

Loader startup calls `ReadLocalAsync` only. A caller may schedule and await `RefreshAsync` later; unavailable packs do not prevent startup. Cache and fallback directories are supplied by the host. Refresh checks are throttled per release tag and pack ID for at least one hour, including failures. A different tag bypasses freshness. Valid cache envelopes persist the tag, successful check time and ETag; conditional requests require a valid matching cache. A 304 without one triggers a full GET. Cache envelopes replace atomically. The transport owns a SocketsHttpHandler with automatic redirects disabled and validates every manual redirect before sending (maximum five). Only HTTPS github.com, objects.githubusercontent.com and release-assets.githubusercontent.com are accepted. A handler factory exists solely for offline tests. Asset reads are streamed with a configurable 32 MiB default limit, including responses without Content-Length. Release tags and asset names allow only ASCII letters, digits, dots, underscores and hyphens, rejecting empty strings and `..`.

## Manual release workflow

In GitHub Actions, select **Release PoE1 data packs** (`release-packs.yml`) and **Run workflow** on the intended revision. Enter a pack version such as `3.29.3.4-1`. Versions must match `^[A-Za-z0-9]+([._-][A-Za-z0-9]+)*$` and must not end in `.lock`, ensuring a valid git tag. Leave the RePoE SHA blank to use `repoe.json`, or supply an explicit full 40-hex commit. Before downloading, the workflow checks the GitHub compare API to ensure the chosen commit is reachable from upstream `repoe-fork/repoe-fork.github.io` `master` (compare status `ahead` or `identical`); fork-only or diverged commits are rejected. Keep **dry_run** enabled (the default) to test and inspect the downloadable `poe1-packs` workflow artifact without creating a release. **prerelease** defaults to true; disable it only when intentionally publishing a stable pack release.

The workflow installs the exact SDK from `global.json`, runs DataGen tests, fetches `data/base_items.json`, `data/mods.json` and `data/stat_translations.json` from the pinned raw.githubusercontent.com URLs without redirects, and generates packs. It checks SHA256SUMS, exact content hashes, cache bytes, source/input provenance, attribution, schema/pack identities and the loader's default content-size limit before uploading the artifact (retained for 14 days). SDK/package setup uses the normal .NET installation and restore infrastructure; game-export fetches use only GitHub hosts.

With **dry_run** disabled and the workflow dispatched on **main** (`refs/heads/main`), a separate job uses only GITHUB_TOKEN with contents-write permission to create `poe1-packs-<version>` as a draft, upload assets, and publish it. It never marks a pack release as the repository's latest application release. The job checks for an existing release or draft before creation and fails clearly if one exists; choose a new version. Existing tags/releases are not overwritten. If upload fails, inspect the retained draft before retrying.

Publishing uses the **release** GitHub environment. The owner should configure a required reviewer in repository **Settings → Environments → release**. The workflow also works with no environment protection rules; in that case publishing proceeds without a reviewer. Runs on other branches can build artifacts but cannot publish. Build and publish jobs have 20-minute and 10-minute timeouts respectively.

Release assets are `poe1-bases.json`, `poe1-mods.json`, `poe1-stats.json`, their `.manifest.json` and `.pack.json` counterparts, and `SHA256SUMS`. The workflow artifact also includes `RELEASE-NOTES.md`; its attribution and source SHA become the release body. The manifest pack version remains the full source SHA: the workflow's version labels the release only. Tier estimates are included in the mods pack. No separate tiers asset is emitted.

Pass the exact `poe1-packs-<version>` tag to `PackLoader.RefreshAsync`. It downloads the `.manifest.json` and `.json` assets from `https://github.com/DaAwesomePwner/ExileSight/releases/download/<tag>/`; no latest-release lookup is involved. The `.pack.json` files are validated cache/fallback envelopes for offline use. Publish in that repository for the current loader to find the assets.

CI verifies all three packs with verify-packs.py, uploads ExileSight-Packs-poe1, and copies only .pack.json envelopes, ATTRIBUTION.txt and a matching SHA256SUMS under packs/poe1 in portable and Velopack outputs. All pack artifacts carry a human-readable attribution notice covered by their checksums. App fallbackDirectory wiring is a separate task. Generated packs are never committed.


## Stat text contract

Call `StatText.StripCopySuffixes` before `Match` for advanced-copy lines. It removes only trailing, space-separated `(crafted)`, `(implicit)`, `(fractured)`, `(enchant)` and `— Unscalable Value` annotations, including stacked suffixes; unknown text remains literal. Match itself stays anchored. Advanced numerical annotations such as `45(10-50)` retain the rolled value, while range-only text retains endpoints.

Each multiline variant has a compiled regex per nonempty line. PackCodec prewarms the weak-key cache when loading a pack; synthetic entries compile lazily. Treat translation arrays as immutable after load. Regex timeouts fail closed. Matching one line returns only that line's stat IDs; it cannot establish conditions on other lines. Callers must combine candidates and validate the complete mod. Rendering still returns the complete multiline tooltip.

Numeric semantics follow the [PyPoE TranslationQuantifier definitions linked by RePoE](https://github.com/OmegaK2/PyPoE/blob/dev/PyPoE/poe/file/translations.py): per_minute_to_per_second divides by 60 and rounds to 1 dp; its explicit Ndp variants use N dp. Milliseconds divide by 1000, optionally rounding to N dp. divide_by_one_hundred_2dp divides by 100 then rounds to 2 dp. Optional-precision forms use the same precision and suppress trailing zeros. Midpoints use decimal round-to-even, matching Python round's intended rule without binary floating-point artifacts. divide_by_two/ten/fifteen_0dp use floor division. old_leech_percent divides by 5; old_leech_permyriad divides by 500. canonical_line and canonical_stat are identity metadata. These are semantic implementations, not copied upstream code.

Output uses invariant decimals without trailing zeros. Reverse matching enumerates the integer raw values that reproduce the displayed value (bounded to 10,000 candidates), and returns their inclusive range, clipped to non-negated conditions. Thus `33.3` per second yields raw `1996–2000`, not a guessed `1998`. Unknown transforms, disjoint negated-condition ranges, excessive inverse ranges, overflows and multiple rounding stages fail closed. Partial multiline candidates require caller-level combination.

Use `--coverage-report <path>` with DataGen to measure reachable, non-hidden English template lines at every packed mod's minimum and maximum endpoints. Each mod/endpoint/line counts separately. The report also counts stat occurrences with no translation. This is a reproducible endpoint probe, not coverage of every roll or evidence from a real client.

Pinned-export endpoint probe (d0bc438357d849bb93ad22f3db0b12938aaf6da1): 12,648 of 84,371 reachable template-line probes remain unmatched (14.9909%). Separately, 15,081 mod-stat occurrences have no non-hidden translation in this export. This broad mods-pack metric includes non-equipment domains; it is not a percentage of player-visible equipment lines. Unsupported lookup/composite handlers and unrecoverable ignored stats remain fail-closed limitations.

Phase 3 also emits guide, mapmods, events and leagues under schema 3 (the envelope is unchanged).
`fetch-inputs.py <directory> [repoe-sha]` downloads all seven pinned inputs without redirects.
Pass that directory to `--source-dir`; no network is used in that mode. Generated packs stay outside git.
The guide preserves Exile-UI display markup, ordered pages, conditions, area advancement tokens and level hints.
Quest identifiers normalize RePoE quest names and strip Exile-UI reward-page suffixes; only quest rewards are joined.
Non-gem placeholders (including vendor-only Fallen from Grace) remain display hints, with no invented reward list.
Map modifier IDs group alternative patterns with identical labels; differing labels retain separate entries with the same stable rating ID; `|` separates required lines and `#` marks numbers. Ratings are never packed.
Events and historical leagues are ExileSight-authored JSON. The league list is deliberately incomplete; null end dates
mean unknown, and current league names come from poe.ninja index-state at runtime.
New pack versions hash both upstream pins and authored input hashes. Mixed-source manifest file keys are pinned raw
GitHub URLs; authored sources use repository-relative paths and content hashes. Existing RePoE pack versions stay unchanged.
