# Data pack generation

Run `dotnet run --project tools/ExileSight.DataGen -- poe1 --repoe-sha <full-40-digit-sha> --out <directory> [--source-dir <local-export>]`.
Only base_items.json and mods.json are consumed. Local input hashes are recorded but local input provenance cannot be authenticated by the converter.
Never commit generated game data or publish release assets until the owner clears redistribution.

Schema 2 emits content, manifest, a local cache envelope, and SHA256SUMS. All output uses fixed LF newlines and invariant JSON formatting. Content hashes cover exact emitted UTF-8 bytes; cache envelopes retain those bytes as base64 and validation never re-serializes content. Schema 1 envelopes must be regenerated. Pack version is the full source commit. `gamePatch: unknown` and Unix epoch `generatedAt` are explicit unknown sentinels: the export does not provide trustworthy patch/time metadata, and wall-clock timestamps would break reproducibility. Input bytes and SHA fully determine output.

Tier estimates group by domain, generation type, groups and stat IDs within an item class and complete base-tag set. The first matching spawn weight determines eligibility, including zero-weight exclusions. Only item-domain prefix/suffix mods on item-domain bases are ranked; implicit, corrupted, crafted-domain and other unsupported mods remain explicitly unranked. Identical eligible family ladders are stored once, with class/tag contexts referencing stable hash IDs. Descending required level gives dense ranks (equal levels tie and ordinal mod IDs give stable ordering); these are level-order estimates, not official tiers or guaranteed power rankings. Stat IDs serve as unresolved text-template lookup IDs; translated text is not bundled. Unique drop tiers remain null/unknown.

Loader startup calls `ReadLocalAsync` only. A caller may schedule and await `RefreshAsync` later; unavailable packs do not prevent startup. Cache and fallback directories are supplied by the host. Refresh checks are throttled per release tag and pack ID for at least one hour, including failures. A different tag bypasses freshness. Valid cache envelopes persist the tag, successful check time and ETag; conditional requests require a valid matching cache. A 304 without one triggers a full GET. Cache envelopes replace atomically. The transport owns a SocketsHttpHandler with automatic redirects disabled and validates every manual redirect before sending (maximum five). Only HTTPS github.com, objects.githubusercontent.com and release-assets.githubusercontent.com are accepted. A handler factory exists solely for offline tests. Asset reads are streamed with a configurable 32 MiB default limit, including responses without Content-Length. Release tags and asset names allow only ASCII letters, digits, dots, underscores and hyphens, rejecting empty strings and `..`.
