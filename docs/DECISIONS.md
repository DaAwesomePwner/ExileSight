### P1-T7 Windows owner check

- On a fresh user account, start the installed artifact: verify the four setup pages, detected candidates and Browse validation; Cancel exits without saving setup. Inspect the current hotkeys and read/privacy disclosure.
- Finish with a readable log, then relaunch: only the tray appears. Its tooltip is ExileSight; Debug panel opens and closing it hides it. Verify Run setup again, Open settings folder and Exit.
- Cancel a setup rerun and confirm the saved path is unchanged. Finish with another log and confirm only new entries in that log appear. Existing historical lines must not appear. Area entries and level-ups update diagnostics; chat shows event type only, with no body or player name.
- Check Windowed and Windowed Fullscreen overlays; the fullscreen warning must not inspect or change game configuration. Run setup with a missing/locked log and confirm validation blocks Finish.
- Restart Windows Explorer and confirm the tray icon returns once, with the same tooltip and working menu. Check left/double-click opens diagnostics, right-click and keyboard context-menu activation open the WPF menu, and clicking elsewhere dismisses it. Exit removes the tray icon.
- Exit normally with a staged update and confirm the updater's existing apply-on-exit path. A newer settings schema must remain untouched and display a read-only save error if setup is needed.

### P0-T1 verification notes

- Metadata tests verify GetForegroundWindow from Input and GetWindowRect from Window in the production assembly. A successful one-off build with GetForegroundWindow in both files confirms CsWin32 0.3.369 deduplicates shared entries; either spike may list a shared API independently.
- Analyzer negative probe: temporarily append `SendInput` to Input/NativeMethods.txt and add a source method outside ActionGate.cs calling `global::Windows.Win32.PInvoke.SendInput(0, null, 0)` in an unsafe context. `dotnet build src/ExileSight.Platform.Windows -warnaserror` exits 1 with **RS0030 at the probe call**. Moving that probe to Input/ActionGate.cs with its file-local pragma exits 0. Both temporary sources and the additional native entry were removed afterward; no input was executed.
- Documentation IDs were extracted with `dotnet build src/ExileSight.Platform.Windows -p:GenerateDocumentationFile=true -p:NoWarn=CS1591` while temporarily requesting the banned APIs. CsWin32's default wideCharOnly normalizes PostMessageW/SendMessageW to unsuffixed names; explicit A/W entries cover alternate settings too.
- Analyzer format: [official BannedApiAnalyzers documentation](https://github.com/dotnet/roslyn/blob/main/src/RoslynAnalyzers/Microsoft.CodeAnalysis.BannedApiAnalyzers/BannedApiAnalyzers.Help.md). Generator settings: [official CsWin32 schema](https://github.com/microsoft/CsWin32/blob/main/src/Microsoft.Windows.CsWin32/settings.schema.json).

### P0-T1 review-fix verification notes

- Ban coverage now reads actual test-inventory method metadata and reconstructs exact documentation IDs, including suffix variants. Every generated restricted method must have an entry. BCL entries resolve against runtime assembly metadata; explicitly marked SPECULATIVE entries cover disabled friendly/SafeHandle/A/W projections and the unreferenced WinForms type. InputInjector is resolved against the actual Windows 19041 reference projection.
