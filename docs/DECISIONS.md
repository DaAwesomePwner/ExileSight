### P0-T1 verification notes

- Metadata tests verify GetForegroundWindow from Input and GetWindowRect from Window in the production assembly. A successful one-off build with GetForegroundWindow in both files confirms CsWin32 0.3.369 deduplicates shared entries; either spike may list a shared API independently.
- Analyzer negative probe: temporarily append `SendInput` to Input/NativeMethods.txt and add a source method outside ActionGate.cs calling `global::Windows.Win32.PInvoke.SendInput(0, null, 0)` in an unsafe context. `dotnet build src/ExileSight.Platform.Windows -warnaserror` exits 1 with **RS0030 at the probe call**. Moving that probe to Input/ActionGate.cs with its file-local pragma exits 0. Both temporary sources and the additional native entry were removed afterward; no input was executed.
- Documentation IDs were extracted with `dotnet build src/ExileSight.Platform.Windows -p:GenerateDocumentationFile=true -p:NoWarn=CS1591` while temporarily requesting the banned APIs. CsWin32's default wideCharOnly normalizes PostMessageW/SendMessageW to unsuffixed names; explicit A/W entries cover alternate settings too.
- Analyzer format: [official BannedApiAnalyzers documentation](https://github.com/dotnet/roslyn/blob/main/src/RoslynAnalyzers/Microsoft.CodeAnalysis.BannedApiAnalyzers/BannedApiAnalyzers.Help.md). Generator settings: [official CsWin32 schema](https://github.com/microsoft/CsWin32/blob/main/src/Microsoft.Windows.CsWin32/settings.schema.json).

### P0-T1 review-fix verification notes

- Ban coverage now reads actual test-inventory method metadata and reconstructs exact documentation IDs, including suffix variants. Every generated restricted method must have an entry. BCL entries resolve against runtime assembly metadata; explicitly marked SPECULATIVE entries cover disabled friendly/SafeHandle/A/W projections and the unreferenced WinForms type. InputInjector is resolved against the actual Windows 19041 reference projection.
- Alternate projection IDs were harvested with temporary CsWin32 friendly/SafeHandle/A/W settings and XML documentation output. Analyzers were disabled only for that signature-inventory build because generated wrappers call banned methods; this was not a verification build. Settings were restored before the normal analyzer-enabled build and tests. No exemption is persisted. Tests retain coverage for production signatures regardless of speculative entries.
- The PE regression fixture inspects the test-only native inventory without loading or invoking native code; Reflection.Emit import and calli APIs are now banned too. Production tests inspect exact bin/configuration/TFM outputs, rather than searching arbitrary old binaries.
- Review-fix negative probe: with `TreatWarningsAsErrors=false`, temporary calls to Process.Kill, NativeLibrary.Load, SendMessageTimeout and SendMessageCallback each produced RS0030 errors. The probe was removed before final verification; no native calls ran.

### Final review-round verification notes

- CsWin32 duplicate-input/API compatibility probe: temporarily requested GetForegroundWindow in both production files, plus MsgWaitForMultipleObjectsEx, GetMessage/PeekMessage/TranslateMessage/DispatchMessage, SetWindowsHookEx/UnhookWindowsHookEx/CallNextHookEx, SetWinEventHook, OpenClipboard/GetClipboardData/SetClipboardData/EmptyClipboard/CloseClipboard and GlobalAlloc/GlobalLock/GlobalUnlock. The analyzer-enabled build exited 0; temporary additions were restored. These APIs remain unbanned. PostMessage/PostThreadMessage remain banned; hook shutdown uses an event plus MsgWaitForMultipleObjectsEx.
- Guard tests restore one isolated project from the already populated NuGet cache, import mutation targets after SDK targets, await every child process via its exit event, and remove the temporary tree in finally. Temporary projects live under obj and are excluded before repository traversal. No analyzer-disable exemption exists for tests or the inventory.
- Reflection.Emit DefinePInvokeMethod (including the protected core path), EmitCalli and DynamicMethod are banned, as are Process.HasExited, WaitForExit/WaitForExitAsync and priority/affinity setters. Process.Refresh, name and ID access remain allowed.
- Process accessor probe found that method-only setter bans do not flag property-assignment syntax. PriorityClass and ProcessorAffinity therefore also have property bans (reads are conservatively forbidden as well). The hermetic compiler regression checks these assignments, HasExited, both wait forms, DynamicMethod, EmitCalli and DefinePInvokeMethod for RS0030; its baseline confirms Refresh, Id and ProcessName still compile.
- Production-inventory negative probe: temporarily generating OpenProcess still compiles, but the focused metadata test exits 1 with "Restricted API shipped in production". The entry was restored before the final full build/test.

### Extra review-round verification notes

- The analyzer allowlist was enumerated from resolved Analyzer items for every project in ExileSight.slnx. It stores exact package versions and file paths with portable SDK/cache roots, not machine-specific paths or wildcard package directories.
- Independent audits execute Compile with SkipCompilerExecution=true and BuildProjectReferences=false so resolution, user targets and guards run without rewriting loaded test assemblies. Audits use the test run's Debug/Release configuration. Three project audits run concurrently; each child is bounded. Negative audits cover both disabled imports, both import-path overrides, each empty guard, spoofed success markers plus intermediate NoWarn, and an extra analyzer despite spoofed markers.
- Compiler negative builds additionally cover late _SkipAnalyzers, scalar/item CompilerResponseFile with /skipanalyzers+ and /nowarn:RS0030, and an extra analyzer. Temporary trees are removed in finally after all children exit. Source negative tests cover each import/skip/response/guard-override token.
- The CI-equivalent single-file publish activates two additional SDK ILLink 10.0.14 analyzers; their observed exact paths are pinned too. The guard task returns failure immediately after logging any violation, rather than merely relying on the final MSBuild error count.

### Ban-scope correction

- Removed the test process runner's RS0030 pragma and the scanner exception. The source scanner applies the same suppression rule to tests as to every other hand-written file; only the future Platform.Windows/Input/ActionGate.cs is exempt.
- Global bans remain in BannedSymbols.txt for every project. Only managed System.Diagnostics.Process member bans moved to BannedSymbols.Production.txt. Path-based selection includes every project under src/ and tools/, regardless of project name, and excludes tests/.
- Compiler guard fixtures now live under src/ExileSight.Core/obj so negative Process-compilation tests exercise actual production scope. Dedicated negative cases remove only the production list, retaining the global list, and verify both the build guard and independent audit reject that state. Every solution project's independent audit also checks the production list is absent from tests.
- FAIR-PLAY.md needs no wording change: its described input-synthesis and process-memory APIs remain in the global BannedSymbols.txt, and its sole-suppression rule is unchanged.
